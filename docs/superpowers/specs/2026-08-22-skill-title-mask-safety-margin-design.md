# 技能标题蒙版安全余量增量修复设计

## 目标

修复 Methods & Skills 区域中 `Algorithms` 和 `Writing` 的字母下行笔画在部分浏览器缩放、设备像素比或字体栅格化条件下被标题蒙版底边裁切的问题，同时保留现有瀑布揭示动画和版式位置。

## 已验证现状

- 标题由 `.skill-title-mask` 的 `overflow: hidden` 形成揭示蒙版。
- 当前样式已使用上下各 `0.12em` 的内边距，并用负外边距补偿版式。
- 在与问题截图一致的 `2408 × 1104` 视口中，当前本地构建的标题底部到蒙版底边只有约 `3.2px` 余量。
- 同一视口下，将蒙版临时改为 `overflow: visible` 前后的局部截图完全一致，因此当前测试环境没有发生实际裁切；本次修改属于针对浏览器字体栅格化差异的安全余量增强。

## 方案

只调整技能标题专用蒙版：

- 将顶部和底部内边距从 `0.12em` 增至 `0.18em`。
- 将顶部负外边距同步改为 `-0.18em`。
- 将底部补偿改为 `calc(0.25rem - 0.18em)`，保持标题蒙版的外部占位不变。
- 保留 `overflow: hidden`，不引入动画结束后的 JavaScript 状态切换。

这会把最终字形安全余量提高到约 `4.8px`，同时预计仍为标题初始 `translateY(115%)` 状态保留超过 `0.5px` 的完全隐藏间隙。

## 测试设计

先修改浏览器回归断言，使当前 `0.12em` 实现失败，再修改生产样式：

1. 在 `2408 × 1104` 视口测量标题元素底边到标题蒙版底边的最终几何余量，要求不少于 `4.5px`。
2. 继续要求标题初始状态位于蒙版底边之外至少 `0.5px`，避免扩大安全区破坏瀑布揭示。
3. 更新静态 CSS 契约测试，锁定 `0.18em` 的补偿关系。
4. 运行全部单元测试、生产构建和现有响应式浏览器 QA。
5. 在 `2408 × 1104` 以及现有桌面、平板、移动端视口检查 Methods & Skills 截图。

## 不变项

- 不改变标题文案、字体、字号、行高和横向布局。
- 不改变四张技能卡片、图标、分隔线或正文位置。
- 不改变标题和正文的瀑布动画时序。
- 不修改其他区块的通用蒙版。
- 不部署生产环境，也不推送 `main`。

## 验收标准

- `Algorithms` 和 `Writing` 的下行笔画完整可见。
- 标题最终底部安全余量不少于 `4.5px`。
- 标题动画初始隐藏间隙不少于 `0.5px`。
- 标题基线和正文起点相对修改前的偏移不超过 `0.5px`。
- 所有自动化测试、构建和响应式视觉回归通过。

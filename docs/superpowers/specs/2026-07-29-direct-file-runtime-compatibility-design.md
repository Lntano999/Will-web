# Will-web Direct-file Runtime Compatibility Design

**Date:** 2026-07-29
**Status:** Approved approach, pending implementation
**Scope:** Repair the `file://` regression introduced by runtime self-hosting without changing the site's visual design or production dependency strategy.

## Problem

Will-web currently references self-hosted animation assets with root-absolute URLs such as `/vendor/gsap/gsap.min.js`.

This is correct when the page is served by Vite or Vercel because Vite maps `public/vendor/` to `/vendor/`. It is incorrect when the repository's `index.html` is opened directly: the browser resolves the URL against the disk root and requests `file:///C:/vendor/...`, while the real files are under `./public/vendor/...`.

The dependency-free fail-open releases the preloader and restores native scrolling, but GSAP, Lenis, ScrollTrigger, SplitText and anime.js remain unavailable. The visitor therefore sees a static degraded page instead of the intended branded motion.

## User outcome

The same source checkout must support both entry modes:

1. Direct inspection by opening `index.html` as a `file://` URL.
2. Development, production build and deployment through Vite/Vercel over HTTP.

Both modes must load the self-hosted animation runtimes. Direct-file compatibility must not reintroduce public runtime CDN dependencies or duplicate vendor assets.

## Approved architecture

The source HTML will use the disk-valid prefix:

```text
./public/vendor/
```

`vite.config.mjs` will expose one narrowly scoped HTML transformation:

```text
source index.html              Vite dev/build output
./public/vendor/...     →      /vendor/...
```

The transformation will run as a `transformIndexHtml` pre-hook so Vite processes the served form of the URLs. Directly opening the untransformed source continues to use the physical `public/vendor/` directory.

The path transformer will be a named exported function. This keeps the behavior independently testable instead of hiding it inside an anonymous configuration callback.

## Data flow

### Direct file

```text
index.html
  → ./public/vendor/...
  → files generated by sync-vendor-assets.mjs
  → browser loads runtimes from disk
```

### Vite development and production

```text
index.html
  → transformIndexHtml pre-hook
  → /vendor/...
  → Vite public-directory mapping
  → dist/vendor/...
  → browser loads runtimes from the site origin
```

## Failure handling

The existing dependency-free preloader fail-open remains unchanged. It is still the final safety layer if files are missing or blocked, but it is not considered a substitute for successful runtime loading in either supported entry mode.

No new network fallback will be added. A missing local runtime must remain visible to automated QA rather than being masked by a CDN request.

## Verification contract

Implementation is accepted only when all of the following pass:

1. A regression test proves the source HTML contains the six approved `./public/vendor/` references.
2. A configuration test executes the exported transformer and proves the served HTML contains `/vendor/` references without `./public/vendor/`.
3. Vite build output contains the nine allowlisted runtime and licence files.
4. A direct-file browser QA blocks third-party HTTP resources and verifies:
   - GSAP, ScrollTrigger, SplitText, Lenis and anime.js are available;
   - the preloader completes normally instead of using `animation-runtime-unavailable`;
   - navigation is visible and scrolling progresses;
   - no request targets `file:///C:/vendor/...`;
   - no page errors occur.
5. Existing HTTP QA still passes six responsive viewports with same-origin runtimes.
6. Existing forced-vendor-block QA still passes at 1440px and 390px through fail-open.
7. Visual evidence is reviewed for the direct-file hero and the existing HTTP/fallback captures.

## Scope boundary

This repair does not:

- split the monolithic HTML or migrate inline scripts to ES modules;
- change animation parameters, copy, layout or visual styling;
- localize jQuery, Webflow runtime or Unicorn Studio;
- merge, push or deploy the branch.

## Rollback

The repair will be isolated in a dedicated commit on `codex/portfolio-industrialization`. Reverting that commit restores the previous HTTP-only self-hosted path behavior without affecting the earlier runtime-locking commits.

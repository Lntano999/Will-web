# 基于 Will-web 的前端工程知识库重构设计

**日期：** 2026-08-12

**适用范围：** Obsidian Vault `D:\Obsidian--notes\notion\前端知识\` 与配套《Web 产品工程 16 周学习执行计划（AI 协作型）》

**目标：** 保留既有原子笔记和双链，把知识库从术语列表重构为面向 Web 产品交付生命周期的工程知识地图，并把对应笔记接入 16 周学习计划。

## 1. 边界与命名

- 保留磁盘文件夹名 `前端知识` 和入口文件名 `前端知识.md`，避免破坏既有路径引用。
- 将入口页 H1 标题改为“基于 Will-web 的前端工程知识库”。
- 明确该知识库记录真实项目中出现的可复用工程概念，不替代系统课程周笔记。
- 通用缩写和工具沿用官方名称，例如 DNS、DOM、CSP、CI、Vite、Playwright、Vercel；在 MOC 中补充中文职责说明。
- 中文工程概念使用稳定、可检索的名称，例如“依赖本地化”“构建产物”“视觉回归”。
- 不为统一外观批量重命名全部原子文件；优先通过 MOC 显示名、正文 H1 和 frontmatter aliases 提升可读性。

## 2. MOC 信息架构

入口 MOC 采用 Web 产品交付生命周期作为一级顺序：

1. 使用说明与知识边界；
2. 产品定义与工程决策；
3. 浏览器如何运行网站；
4. 源码与模块边界；
5. 依赖与构建系统；
6. 测试与可靠性；
7. 发布、网络与运行环境；
8. 安全与故障恢复；
9. Will-web 关键工程案例。

每个分区先用一到两句话说明它在交付链路中的职责，再列出相关原子笔记。入口页不是术语正文，不复制原子笔记内容。

Will-web 案例区只链接已经有可靠证据或现有笔记支撑的案例，包括预加载器 fail-open、第三方依赖本地化、`file://` 与 HTTP 差异、源码渐进拆分和视觉回归保护。尚未形成独立案例笔记的主题用“阅读路径”链接已有概念，不虚构事故结论。

## 3. 16 周计划协同

在主计划每一周加入“项目知识库建议阅读”小节，位置放在核心概念之后、官方材料之前。每周使用统一说明：

> 以下建议基于截至 2026 年 8 月 12 日的知识库状态，用于把课程概念连接到 Will-web 实例，不替代本周官方材料和亲手实验。

每周选择 2–5 篇确实相关的原子笔记，并为每篇标注阅读目的和时点：

- **预习：** 先形成最小心智模型；
- **实验时查阅：** 遇到对应工具或故障时使用；
- **复盘：** 完成实验后校正原有理解。

若某周缺少合适的项目笔记，应明确说明暂无对应笔记，不为了数量创建空洞条目。

执行手册增加三段式使用规则：学习前阅读建议原子笔记并写预测；学习中以独立练习和工具证据为主；学习后用自己的话完成周笔记，并只在产生可复用认识时更新原子笔记。

## 4. 内容流与职责边界

```text
16 周主计划：规定每周学什么、做到什么程度
        ↓
每周学习笔记：记录个人预测、实验、证据与复盘
        ↓
前端工程知识库：沉淀跨周复用的概念和 Will-web 实例
```

- 主计划不能被原子笔记替代。
- 原子笔记不复制整周学习过程。
- MOC 只负责导航、顺序和概念关系。
- 网站生产代码不因本次笔记重构而修改。

## 5. 异常处理与链接安全

- 写入前备份所有目标 Markdown 文件。
- 保留原文件夹和入口文件名，降低外部链接失效风险。
- 更新后扫描所有 `[[双链]]`，确认目标文件存在；无法解析的链接必须列出并人工判断。
- 所有文件使用 UTF-8，写入后重新读取中文标题，防止出现乱码。
- 16 个周次必须各有且只有一个建议阅读小节，并统一带有 `2026-08-12` 时点说明。
- 不修改学习计划中的周目标、时间预算、必做练习和验收问题。

# Will-web 网站产品化与工程化升级设计

**日期：** 2026-07-29

**状态：** 已完成方向确认，等待用户复核书面规格

**基线提交：** `d7f84564d8321fd59ab8c2151dde723233751c9d`

## 1. 目标

在保留 Will-web 现有高级、克制视觉身份和品牌动效的前提下，将网站升级为可长期维护、可自动验证、可安全发布和可快速回滚的个人作品站。

升级后的站点继续服务所有访客，职业主线保持为“量化开发 × 金融科技后端”。网站仍采用静态托管；本轮不引入账户、数据库、鉴权、支付或传统后端。

## 2. 已验证基线

- `HEAD`、`main` 与 `origin/main` 均指向基线提交。
- 基线 worktree 原为 detached HEAD，正式文档与后续实现使用独立 `codex/portfolio-industrialization` 分支。
- `index.html` 为 2,963 行、128,588 字节；主 CSS 为 6,160 行、111,401 字节。
- 页面包含 24 个 script，其中 11 个为外部运行时；另有 7 个内联 style、21 个 style 属性和 7 个图片 `onerror`。
- 页面当前没有 `main` 和 `h1`，只有一个语义 `section`，存在 8 个 `href="#"`。
- Node 静态回归测试实测 18/18 通过。
- Playwright 离线 QA 在 1920、1440、1024、768、390、360 六档视口实测通过；所有第三方资源被阻断时，预加载器仍会释放，页面恢复导航和滚动。
- `https://will-tech.xyz/` 当前由 Vercel 返回 308 并跳转至 `https://www.will-tech.xyz/`；`www` 返回 200。
- 生产 HTML 的 ETag 与基线 `index.html` 的 MD5 一致，当前线上首页与本地基线相同。

## 3. 产品原则

### 3.1 保留的内容与视觉资产

- “用代码构建 → 用模型分析 → 到真实世界调研 → 再把答案讲清楚”的首页叙事。
- Build / Model / Field / Speak 四组横向经历。
- 四组同源 SVG 图形及其构建时序。
- 瀑布蒙版、固定断句、红色标志和线条入场。
- 结尾页与 Methods & Skills 已确认的 reveal timing。
- 正常模式下的品牌动效、reduced-motion 降级和离线可读性。

### 3.2 内容真实性

- 英语口语以英式发音为主。
- 青衿文化桥英语演讲比赛一等奖。
- `CN Stories 英语演讲大赛`广东省二等奖，不得写作 `CN Story`。
- 作为队长参加电工杯数学建模大赛并获全国三等奖。
- 暑期随学院院长赴陆丰参与省级调研项目；共同负责调研日志、PPT/文书和新闻稿初稿；公开稿件发布于南方+。
- 允许删减经历，但不得无证据扩大个人职责、奖项范围或专业能力。

### 3.3 明确不做

- 不为了“高级感”全面更换视觉风格或前端框架。
- 不把静态作品展示误解为必须增加后端。
- 不改写为量化研究定位。
- 不为家教场景增加独立入口或降低公共站点的专业表达。
- 不要求用户手写全部前端代码，也不让网站任务取代系统课程学习。

## 4. 方案选择

采用 **Vite + 原生 HTML/CSS/JavaScript 模块** 的渐进迁移。

Vite 只承担开发服务器、模块解析、依赖打包和静态产物生成，不引入 React、Vue 或客户端内容渲染。迁移初期保持现有 DOM、类名、固定断句和 SVG 不变，避免构建体系接入与视觉重构同时发生。

未选择 Astro 的原因是当前动效高度依赖具体 DOM 和样式所有权，组件化迁移会扩大首轮视觉回归面。未选择继续无构建体系，是因为它不能充分解决依赖本地化、版本锁定、产物验证和 CI。

### 5.1 内容边界

核心内容继续在构建阶段生成的 HTML 中存在，不依赖客户端 JavaScript 注入。禁用 JavaScript 或增强运行时失败时，身份、经历、证据和联系方式仍可阅读。

本轮不为单页内容提前引入 CMS 或复杂内容数据库。若未来增加多份项目详情页，再基于真实重复模式评估构建时内容数据源。

### 5.2 动效所有权

每个元素只有一个动效控制器。目标元素使用明确的 `data-motion` 或等价属性声明控制权，避免 Webflow、GSAP、IntersectionObserver 与 CSS 同时修改同一个 `transform` 或 `opacity`。

预加载释放保持以下性质：

- 最早安装；
- 不依赖 GSAP、anime.js、Lenis 或 Webflow；
- 释放操作幂等；
- 动画运行时缺失时立即释放；
- watchdog 超时后释放；
- 恢复导航、滚动和必要最终态。

### 5.3 依赖策略

- GSAP、ScrollTrigger、SplitText、Lenis 与 anime.js 使用锁定版本并纳入本地构建。
- InertiaPlugin 与 Draggable 当前只有注册、没有功能调用；验证后删除。
- jQuery 没有自定义调用；在复刻并验证唯一 Webflow interaction 后，与 Webflow runtime 一起删除。
- Unicorn Studio 只作为可选背景增强，不能成为内容、导航、滚动或预加载依赖。
- 图片加载失败使用同源资源、纯色或安全隐藏，不再跳转到 Unsplash。

### 5.4 响应式策略

- 桌面端保留现有横向 pin、四组 SVG 构建和最终覆盖逻辑。
- `767px` 及以下将 Experience 改为按 Build、Model、Field、Speak 顺序排列的纵向阅读流。
- 移动版沿用现有字体、色彩、图形和 reveal 语言，不改成通用卡片模板。
- reduced-motion 模式直接进入完整、可读、可操作的稳定状态。

## 6. 分阶段迁移

### 阶段 0：冻结基线

**范围：**

- 创建独立分支。
- 修正文档中 Cloudflare/Vercel 与预加载旧 P0 状态。
- 固化正常、离线和 reduced-motion 基线。
- 建立桌面横向 SVG、结尾页、Methods & Skills 的关键视觉检查点。

**验收：**

- 静态测试 18/18 通过。
- 六档离线 QA 通过。
- 当前生产站保持不变。
- 基线截图和关键状态可以在统一命令下复现。

### 阶段 1：接入 Vite 与基础 CI

**范围：**

- 增加 Vite 的开发、构建和预览流程。
- 保持 DOM、类名、断句、动画参数和外部运行时不变。
- CI 执行静态测试、构建和最小浏览器冒烟检查。

**验收：**

- 构建生成可独立托管的 `dist/`。
- 本地预览版静态测试和六档离线 QA 通过。
- 预览版与稳定视觉基线一致。
- 不增加新的第三方运行时请求。
- 不部署生产。

### 阶段 2：本地化依赖与收回动效控制权

**范围：**

- 按单个依赖逐步本地打包 GSAP、Lenis、anime.js。
- 将内联动效逻辑拆入职责明确的模块。
- 删除 InertiaPlugin、Draggable 等无实际调用插件。
- 记录并复刻唯一 Webflow interaction，随后移除 Webflow runtime 与 jQuery。
- 保留最早、零依赖的 fail-open。

**验收：**

- 阻断所有站外资源时，GSAP/ScrollTrigger/SplitText/anime/Lenis 的本地运行时仍可用。
- 正常预加载品牌动画可以完成。
- 动画运行时被人为禁用时，fail-open 仍可释放页面。
- 四组 SVG 首次可见时尚未完成，并按既定时序完成。
- 横向结束覆盖、Methods & Skills、结尾 reveal timing 与基线一致。
- 每个动画目标只有一个控制器。

### 阶段 3：语义、SEO 与键盘访问

**范围：**

- 增加 `main`、唯一 `h1`、语义 section 和正确标题层级。
- 将菜单入口改为真正的 button，并维护 `aria-controls`、`aria-expanded`。
- 实现 Enter、Space、Escape、焦点进入和焦点回收。
- 把无目标卡片改为非交互容器；微信复制使用 button；清除所有占位链接。
- 校正图片 alt。
- 增加 canonical、`og:url`、`og:image`、Twitter 图片和 Person/Profile JSON-LD。

**验收：**

- `main` 恰好一个，`h1` 恰好一个。
- `href="#"` 数量为零。
- 键盘可以完成导航展开、跳转、关闭和联系入口操作。
- 焦点始终可见，菜单关闭后返回触发按钮。
- 无 JavaScript 时核心内容与真实链接可阅读。
- SEO 和分享字段指向生产域名及本地分享图。
- 正常与 reduced-motion 视觉回归通过。

### 阶段 4：移动 Experience

**范围：**

- `767px` 及以下取消横向 pin，切换为纵向四段经历。
- 保留图形系统、内容顺序、证据链接和局部 reveal。
- 桌面横向逻辑保持独立，不复用移动状态。

**验收：**

- 360、390、768px 均能连续读完四段经历。
- 不需要横向拖动，不产生文档级横向溢出。
- 四个证据与外部链接均可键盘和触摸操作。
- 1920、1440、1024px 的桌面横向轨道、SVG timing 和最终覆盖不变化。
- reduced-motion 下四段内容立即完整显示。

### 阶段 5：样式、图片与维护结构

**范围：**

- 按 token、基础样式、章节、动效和可访问性拆分 CSS。
- 移除没有必要的内联 style 与图片 `onerror`。
- 为图片补充尺寸，按内容需要生成 WebP/AVIF 或压缩版本。
- 保持核心内容直接存在于 HTML，不进行客户端内容渲染。

**验收：**

- 内联样式只保留经过说明的动态值。
- 远程 Unsplash 回退数量为零。
- 所有本地图像在离线 QA 中成功返回。
- 页面请求数、传输体积、CLS 和移动内存使用不比基线恶化。
- 所有内容、语义、动效和浏览器测试通过。

### 阶段 6：交付、监控与安全响应头

**范围：**

- 建立 Vercel Preview 审查流程和生产发布清单。
- 增加 `Referrer-Policy`、`X-Content-Type-Options`、合理的 `Permissions-Policy`。
- CSP 先使用 Report-Only；验证无误后再单独决定是否强制。
- 增加定时生产 QA，检查根域重定向、`www` 响应和预加载释放。
- 记录 Vercel 上一部署恢复流程。

**验收：**

- 未通过 CI 和预览审核的提交不能进入发布候选。
- 响应头在 Preview 中实测存在且不阻断页面资源。
- 生产监测能识别非 200、错误重定向或预加载未释放。
- 发布清单包含内容真实性、视觉、键盘、离线和回滚检查。
- 未经用户明确批准不推送 `main` 或部署生产。

## 7. 测试策略

### 7.1 静态与结构测试

- 内容真实性和禁用措辞。
- 赛事名称、奖项、个人职责与证据链接。
- 唯一 `main`、唯一 `h1`、section 标题层级。
- 无占位链接、图片 alt、SEO 与 JSON-LD。
- 动效目标和控制器所有权。

### 7.2 浏览器测试

- 1920、1440、1024、768、390、360 六档视口。
- 正常运行时、所有站外资源阻断、关键本地依赖人为缺失。
- 默认运动与 reduced-motion。
- 预加载释放、滚动恢复、导航和键盘焦点。
- 四组横向 SVG 触发与完成。
- 桌面最终覆盖与移动纵向完整阅读。

### 7.3 视觉审核

稳定的离线/reduced-motion 页面使用截图差异检测。动态背景和正常运动模式使用关键状态截图与人工时序复核，避免远程装饰或逐帧变化造成无意义像素噪声。

## 8. 错误处理与降级

- 关键运行时不可用：立即释放预加载并显示静态最终态。
- IntersectionObserver 不可用：内容直接显示。
- 平滑滚动不可用：保留浏览器原生锚点滚动。
- Unicorn 背景不可用：保留稳定背景色或本地视觉层。
- 图片不可用：装饰图安全隐藏，内容图显示同源占位和文字说明。
- 外部证据链接不可达：不阻塞页面；定时 QA 报告但不伪造替代证据。

## 9. 风险与回滚

- 每个阶段独立提交，不能把构建接入、DOM 重构和视觉调整合并成一个不可拆回滚。
- 每次只迁移一个关键依赖；若行为不一致，恢复该依赖上一种加载方式。
- Webflow 删除前先保存其真实效果和浏览器状态，复刻通过后再删除。
- 移动纵向 Experience 只在媒体查询范围生效，桌面控制器保持隔离。
- CSP 先 Report-Only，安全报告通过前不强制。
- 所有高风险提交先进入 Vercel Preview。
- 生产异常时优先恢复上一份已知可靠 Vercel 部署，再回滚对应代码提交。

## 11. 完成定义

本轮产品化与工程化升级完成，需要同时满足：

- 内容真实且公共定位稳定；
- 正常模式保留品牌动效；
- reduced-motion、键盘和移动端可完整使用；
- 关键依赖故障不会阻塞内容；
- 构建、测试、预览、发布和回滚流程可重复执行；
- 内容、样式和动效职责清晰；
- 生产发布经过用户明确批准；
- 工程知识笔记已经记录实施过程中影响决策和验收的关键概念。
